# Standalone Hermite-Simpson planner

This folder descends from the Plan-325 HS3 snapshot at commit
`5a067112a9f880d015f52fb97538a99010871478`. It owns the repository's
Hermite-Simpson motion path, selected with `PlannerMethod="hs3"`.

## Entry points

- `plan.m` normalizes the request, validates endpoints, obtains neutral
  topology proposals, runs actual HS3 solves, independently validates every
  returned trajectory, and selects a validated HS3 candidate.
- `resolvePlannerOptions.m` owns only HS3 controls, including collocation,
  mesh, NLP, collision, seed, and global planning-work limits.
- `validateTrajectory.m` is a compatibility facade over the canonical root
  validator.
- `+internal/+motion` owns the Hermite-Simpson transcription, finite-jerk
  propagation, exact fixed-time affine constraints and derivatives,
  reconstruction, diagnostics, fixed-time `quadprog`, and free-time
  `fmincon` solve.

Neutral request, topology, obstacle, geometry, seed-corridor certification,
result, and polynomial helpers live in `+azElInternal`. Moving-target
interception and final validation remain root-owned.

## Planning behavior

`planAzElMotion("hs3")` returns HS3-specific defaults. On a planning call, the
standalone planner:

1. generates bounded input-driven topology and timed-wait proposals;
2. assigns at least one collocation segment per route leg, subject to the
   configured maximum;
3. solves each attempted proposal with the HS3 transcription;
4. independently validates complete time-parameterized motion;
5. boundedly relinearizes collision constraints and refines the mesh when
   configured; and
6. ranks validated candidates by arrival time, integrated squared jerk, and
   stable seed order.

Timed topology proposals first preserve their input-derived arrival in an
exact fixed-time HS3 problem. A validated timed motion then receives a bounded
fixed-time feasibility bisection that preserves obstacle-event times instead
of rescaling its wait. Static scenes may stop at the first validated motion;
changing obstacle histories retain candidate competition because timing can
change which route is preferable. A validated arrival prunes only spatial
routes whose velocity-only duration bound cannot beat it. Optional free-time
improvement solves receive a cooperative three-second cap unless deterministic
work budgeting was requested.

Successful results set `SelectedMotionSource="hs3"`. Expected no-path or
work-limit outcomes retain the same stable result fields and attempted-solver
diagnostics. Supplied nonzero initial and terminal velocity and acceleration
are enforced by the HS3 boundary equations and checked again by the canonical
validator.

An exact, exhaustive, untruncated static visibility search that rejects the
direct edge returns a diagnosed failure without entering a topology-preserving
motion solve. Reduced or dynamic searches never use this fast exit.

Stationary-obstacle corridor rows constrain the Bernstein hull of the
trajectory over the sub-interval each association owns, not its position at
one instant. Moving and deforming geometry is associated at its ordered
constraint times because freezing one moving shape across an interval would
not certify relative motion. The independent adaptive validator remains
authoritative for every complete time-parameterized trajectory.

`MaximumPlanningTime_s` applies one cooperative wall-time budget across HS3
topology, solving, and validation. Setup and the free-time `fmincon` callback
stop future work; one active function evaluation or fixed-time QP can finish
after the requested deadline. Set `DeterministicWorkBudget` to release that
budget and rely only on the machine-independent caps, so the same request
returns the same motion on a slower or busier machine. A successful finite
search is not a completeness or global time-optimality certificate.

An earliest-arrival solve that stops on the goal horizon never descended, so it
reports `arrivalAtHorizon`, does not end the seed loop, and carries no
earliest-arrival claim in `OptimalityStatement`.

## Size and dependency boundary

The HS3 package has a hard 2,000-nonblank, noncomment-line ownership cap. The
count includes its planner, option owner, validation facade, and motion
internals. It excludes tests, benchmarks, and neutral shared infrastructure.

Optimization Toolbox is required because HS3 motion is generated by
`quadprog` at fixed time and `fmincon` when arrival time is free.
