# Standalone Hermite-Simpson planner

This folder descends from the Plan-325 HS3 snapshot at commit
`5a067112a9f880d015f52fb97538a99010871478`. It now owns a complete standalone
Hermite-Simpson motion path selected with `PlannerMethod="hs3"`.

HS3 and `corridorQuintic` are separate methods. HS3 does not call the compact
planner, consume a compact result or warm start, merge method results, or fall
back to compact motion. Compact results may be measured only by an external
benchmark that submits the same physical request to each public method.

## Entry points

- `plan.m` normalizes the request, validates endpoints, obtains neutral
  topology proposals, runs actual HS3 solves, independently validates every
  returned trajectory, and selects a validated HS3 candidate.
- `resolvePlannerOptions.m` owns only HS3 controls, including collocation,
  mesh, NLP, collision, seed, and global planning-work limits.
- `validateTrajectory.m` is a compatibility facade over the canonical root
  validator.
- `+internal/+motion` owns the Hermite-Simpson transcription, finite-jerk
  propagation, exact fixed-time affine constraints and derivatives,
  reconstruction, diagnostics, and `fmincon` solve.

Neutral request, topology, obstacle, geometry, corridor-certificate, result,
and polynomial helpers live in `+azElInternal`. Moving-target interception and
final validation remain root-owned so both methods receive the same public
contracts without sharing motion implementations.

## Planning behavior

`planAzElMotion("hs3")` returns HS3-specific defaults. On a planning call, the
standalone planner:

1. generates bounded input-driven topology and timed-wait proposals;
2. assigns at least one collocation segment per route leg, subject to the
   configured maximum;
3. solves each attempted proposal with the HS3 transcription;
4. independently validates complete time-parameterized motion;
5. boundedly relinearizes collision constraints and refines the mesh when
   configured; and
6. ranks validated candidates by arrival time, integrated squared jerk, and
   stable seed order.

Timed topology proposals retain their input-derived arrival while being solved
as actual fixed-time HS3 problems. Static scenes may stop at the first validated
motion; changing obstacle histories retain candidate competition because timing
can change which route is preferable.

Successful results set `SelectedMotionSource="hs3"`. Expected no-path or
work-limit outcomes retain the same stable result fields and attempted-solver
diagnostics without substituting another planner. Supplied nonzero initial and
terminal velocity and acceleration are enforced by the HS3 boundary equations
and checked again by the canonical validator.

`MaximumPlanningTime_s` applies one cooperative wall-time budget across HS3
topology, solving, and validation. Setup and the `fmincon` output callback stop
future work, but one active function evaluation can finish after the requested
deadline. A successful finite search is not a completeness or global
time-optimality certificate.

## Size and dependency boundary

The HS3 package has a hard 2,000-nonblank, noncomment-line ownership cap. The
count includes its planner, option owner, validation facade, and motion
internals. It excludes tests, benchmarks, neutral shared infrastructure, and
the separately selectable compact planner.

The current HS3 package can be dispatched and verified without invoking
`+corridor`. Optimization Toolbox is required for HS3 because its motion is
generated by `fmincon`, not by a compact substitute.
