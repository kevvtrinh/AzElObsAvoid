# Az/El planner

Users call the public functions from the parent `planAzElMotion/` product
folder. This package owns the HS3 planner behind the stable public result
contract:

```matlab
options = planAzElMotion();
result = planAzElMotion(obstacles, initialState, goalState, limits, options);
```

`planAzElMotion("hs3")` is the equivalent explicit defaults request. HS3
success always contains motion produced by its Hermite-Simpson transcription
and sets `SelectedMotionSource="hs3"`.

For moving-target interception, place HS3 options inside `PlannerOptions`.
The public `planAzElMovingTargetIntercept` function owns the chronological
fixed-time policy and preserves the common interception result schema.

## Ownership map

```text
+azElPlanner/
|-- plan.m                           planner orchestration
|-- solveSeed.m                      Az/El HS3 seed adaptation
|-- evaluateTrajectoryConstraints.m obstacle/corridor constraints
|-- buildAzElConstraintMatrices.m   fixed-time Az/El matrices
|-- validatePolynomialTrajectory.m  production polynomial certificate
`-- stageTiming.m                   exclusive timing schema
```

`+azElInput` owns request and option processing; `+azElSearch` owns topology
and corridors; `+azElObstacles` and `+azElGeometry` own physical geometry.
The sibling `hs3/` product owns generic polynomial and numerical work.
`solveSeed` translates Az/El corridor constraints into neutral coordinate-space
constraints, then delegates optimization, polynomial reconstruction, and
polynomial evaluation to `hs3Internal`. No numerical solver is called by an
Az/El package.
The public `validateAzElTrajectory` remains the single final validator.

For `GoalTimeMode="fixedArrival"`, every completed candidate keeps the exact
requested arrival time. The planner retains the shortest independently
validated sampled motion within each seed and selects the shortest among all
validated seeds completed inside the existing global work budget. Integrated
squared jerk breaks only path-length ties. This is a bounded candidate-quality
policy, not a global shortest-path certificate. Moving-obstacle fixed-arrival
requests evaluate input-derived seeds in increasing geometric length. Search
stops when an independently validated motion attains the Euclidean start-goal
distance, because no spatially shorter trajectory can exist.

## Dependency and size boundary

The Az/El planner depends inward on the five supporting packages and the
dimension-neutral `hs3/` product; no supporting package depends on planner
orchestration. The parent-folder public functions are the compatibility
boundary. Tests, examples, and benchmarks are outside production ownership.

Optimization Toolbox is required because HS3 motion is generated by
`fmincon`. The finite proposal search and local nonlinear solve do not provide
a completeness or global-optimality guarantee.
